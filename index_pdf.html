①Guildream

2Dギルド経営シミュレーションゲームであり、オフラインイベントでの実演を通じてプレイヤーからのフィードバックを収集し、反映しながら開発を進めてきました。2026年6月にSteam Next Festに参加し、ストアページを公開しました。8月のリリースを控えています。

開発期間2025.02 – 2026.08
開発人員4名チーム
役割ゲームプログラマー
言語C#
エンジン・ツールUnity / Github / Google Sheet / Jira
プラットフォームPC (Steam)

スクリーンショット

  • 1年間プロジェクトを完走し、製品リリースサイクルの全工程を経験。毎週、企画・アートとのミーティングを実施し、Jiraでスプリント管理。
  • クラウドファンディング目標比200%以上達成（目標100万ウォン → 200万ウォン以上の支援）
  • ScriptableObjectベースのEventChannel<T>設計により、Observerパターンを通じたイベント通信を実装
  • オフラインイベントにてGoogle Apps Scriptを活用し、プレイデータをGoogleスプレッドシートへ自動収集するシステムを実装。企画・ディレクターとのデータ駆動型の改善議論に活用。

③「Hanmu Bansa」— 3Dトップビュー・タンクシューティング

3Dトップビューの戦車シューティングゲームで、オンラインマルチプレイ対応です。itch.ioからすぐにプレイできます。
砲弾が壁に無限に跳ね返るのがコアメカニクスです。

開発期間2026.03 – 2026.05
開発人員個人制作
役割すべての役割を担当（3Dオブジェクト、サウンドのみアセットを使用）
言語C#
エンジン・ツールUnity 6 / Github / UGS / NGO
プラットフォームWebGL, PC (itch.io), クロスプレイ対応

スクリーンショット

プレイイメージ
  • シーン遷移時のロビー維持問題 → ネットワークロジックをNetworkBridgeに分離して解決
  • 砲弾反射時の衝突時点での速度変化問題 → FixedUpdateで前フレームの速度を保持する構造に変更して解決
  • Unity ProfilerでフレームごとのUI更新パケット過多送信を原因として特定し、閾値変化時のみパケット送信するよう修正してフレームドロップを解決
  • ジェネリックベースのUIManager設計 — ポップアップのスタック管理・キャッシュ・型安全性の保証
  • WSSプロトコルの統一によりWebGL ↔ EXEのクロスプレイを実現（WebGLはWSSのみサポート）
  • WebGLでのサーバーソケット不可問題 → シングルプレイでもRelay Allocationを作成しホスト経由で解決
  • NetworkManager.Shutdown()の非同期完了前にStartHost()を再呼び出しするとSceneManagerのイベントサブスクリプションが切断される問題 → OnClientStopped＋IsListeningポーリングの組み合わせで完了タイミングを正確に検知して解決
Play https://baramini00.itch.io/hanmu-bansa
GitHub https://github.com/Baramini/HanmuBansa
